Layout rule (the single definition; tests and code refer to it by id):
- L-1 Domain. One pure function lays out the chat body: inputs are the drawable content region of `#chat` in terminal cells (cols, rows), the header fields, the history entries and the state line; output is the list of physical rows to draw, `len(rows) <= rows`, each row <= `cols` cells. The widget draws exactly these rows; nothing else wraps or crops them. The input field is outside this function (Pilot tests cover it). Supported layout: cols >= 20 and rows >= 8. Below it (cols >= 1, rows >= 1): the header is dropped and the rows show the newest history/state rows only, each cut to `cols`; never an error. The supported terminal for the TUI is 80x24 and larger; below it nothing may raise, visibility is not required.
- L-2 Text. Header values: terminal sequences removed, then newline, tab and other control characters shown as escapes (`\n`, `\t`, `\xNN`); a new helper, `planning.clean` removes and is not this rule. History entries and the live text: split on newlines first, then each line gets the same treatment. All widths are measured in terminal cells (wide characters count 2).
- L-3 Header (supported layout): exactly 4 rows, one field each, in this order: model + effort, provider, CODEX_HOME, usage. CODEX_HOME is cut by middle elision (start and end kept); model and provider by end elision. Usage: the full form "ходов N · токенов M" when it fits; otherwise the compact form "х N · т M" where a counter < 1000 is exact and a larger one is floored to one decimal with k/M/G/T (1000015 -> "1.0M", 10**12 -> "1.0T"); >= 10**15 shows "999T+". Counters are integers >= 0. The compact form fits in 20 cells for every value. The full CODEX_HOME stays reachable unshortened in Settings (not through the 256-char `summary`).
- L-4 Body budget (supported layout): after the header, one state row while the chat is preparing, blocked or a turn is running (the live line: whitespace collapsed as `turn_line` does, end-elided to one row); no state row otherwise (completed, cancelled and failed turns show as u3b-chat defines them in the history). The remaining rows (>= 3) are filled with history rows from the newest backwards, after splitting entries per L-2 and wrapping at `cols`, so with non-empty history the last row of the newest entry is always drawn; an entry taller than the budget shows its tail. Empty history: the rows stay empty (or the existing hint, cut to one row).
- L-5 Lifecycle: once MainScreen starts unmounting (quit, screen switch), no render runs; a late update is dropped and never raises.
