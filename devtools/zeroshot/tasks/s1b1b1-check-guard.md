Rules (each: structural rule; domain; boundaries; states; checks in Acceptance):
- R-O Resource ownership. Structural rule: every resource has exactly one owner at a time and a state in {unacquired, owned, borrowed, transferred, released}; only the owner releases it, through a handle whose release is idempotent (a second release is a no-op); no code calls `os.close` on a raw int it does not own, and a released handle never closes again. Domain and owners:
  | resource | owner | others |
  |---|---|---|
  | lifeline pair (zplan end, guard end) | `run_check` from `socketpair()`; the guard end is transferred to the guard by `pass_fds` and the parent copy released right after a successful spawn | — |
  | env pipe (read end, write end) | `run_check`; read end transferred like the guard end; write end owned until the frame is written or refused, then released | — |
  | lease lock fd | `checkout` (from `_lease` until `_forget`) | `run_check` borrows it (never closes it); the guard and group C hold transferred copies |
  | lease pair (lock file + directory) | `_lease` while acquiring, `checkout` after registration | a partially acquired pair (lock created, directory not) releases only the lock it created; never a pre-existing entry or another lease |
  | guard process (Popen and its stdout) | `run_check` after `popen` returns | released by `_reap`, or on an unconfirmed stop transferred to `ORPHANS` (R-C) |
  | group C | the guard | zplan may SIGKILL it after `S` |
  Boundaries: a pair is acquired atomically or not at all; a failure between the two pairs releases the first; a caller descriptor opened on a number this call released earlier survives with its identity (`os.fstat` st_dev/st_ino unchanged). States: before spawn, after spawn before `S`, after `S`, after `X`, in cleanup.
- R-E Environment (closes parent R-1 for `env`). Before any descriptor is acquired, `run_check` snapshots, validates and encodes `env` into one frame; then the frame is handed off completely or the run is refused; never a fallback to the guard's or zplan's own environment. The check (group C leader) sees exactly the encoded entries, byte-exact, and nothing the guard's interpreter added. Closed input domain and outcome:
  | `env` | outcome |
  |---|---|
  | `None` | snapshot of `os.environb` at the call (entries in the same bytes) |
  | `{}` | the empty environment (the check sees no name) |
  | mapping, each name and value `str` | `os.fsencode` of each |
  | mapping, each name and value `bytes` | as given |
  | mapping mixing `str` and `bytes` per name or value | each item encoded independently as above |
  | a name or value of any other type, or `env` not a mapping | `TypeError`, raised before acquisition |
  | empty name, name containing `=` or NUL, value containing NUL | `ValueError`, raised before acquisition |
  A raise from the mapping itself during the snapshot propagates unchanged. Boundaries: 0 entries; 1 entry; a value of 0 bytes; non-UTF-8 bytes; many entries totalling at least 256 KiB (above the 64 KiB pipe buffer, so the write blocks and may be short). States: guard alive and reading; guard gone before reading (broken pipe).
- R-A Argv. A `check["argv"]` element containing NUL raises `ValueError` before acquisition (as `subprocess` would); no descriptor or process is left. A missing executable is `spawn_failed` (parent A-F).
- R-F Failure mapping. Any `OSError` while acquiring or spawning (`socketpair`, `pipe`, `popen`, including `EMFILE`) → `spawn_failed`, empty tail, `duration_s` from the injected clock, every acquired resource released, no guard alive. A lifeline that reaches EOF before `S` or `F` (the guard died before reporting, e.g. its interpreter could not start) → `spawn_failed`, empty tail. EOF after `S` without `X` → status `timeout` (never a numeric status). A handoff refusal (zero-progress write or broken pipe) → `spawn_failed`, empty tail; the guard, seeing a truncated frame, spawns nothing and never falls back.
- R-X Exceptions. The original exception (including `KeyboardInterrupt` and the `ValueError` of R-E/R-A) is the one re-raised after cleanup; an `OSError` inside cleanup is swallowed and never replaces it. An interrupt that arrives during cleanup propagates with the original as its `__context__`; descriptor releases still complete (each in its own `finally`), and the stop counts as unconfirmed (R-C).
- R-C Confirmed stop. Cleanup is successful only when the guard has been reaped within `REAP` and, if `S` was received, `os.killpg(C, 0)` raises `ProcessLookupError`. Otherwise (a `_reap` timeout, an interrupt during the wait, group C still present) the stop is unconfirmed, fail-closed: with an original exception, that exception is re-raised (R-X); with none, `run_check` returns status `timeout` whatever `X` said (an `X 0` never yields status 0 or a passing qualification; return shape and tail unchanged). The unreaped guard `Popen` is then owned by a module-level list `ORPHANS` in checks.py: every later `run_check` entry and every `checkout` exit calls `poll()` on each entry and drops the ones that exited (reaped, never waited on, never killed); `ORPHANS` is the only reference that outlives the call. Every add, poll pass and removal runs under one module-level `threading.Lock` (`ORPHANS_LOCK`): the poll pass takes the lock, keeps the entries whose `poll()` is None and drops the rest in one critical section, so an append from another thread is never lost (the GIL does not make the compound update atomic). If `cwd` is a lease, the lease is marked so that `checkout`'s exit drops the registration and closes its lock fd but does not remove the directory or the lock file (the leftover is s1b1b2's). zplan does not SIGKILL the guard on timeout (before `S` only the guard knows group C).
- R-K Lease cleanup under ownership (critic gate19 point 2). Structural rule: a lease's directory and lock pathname are removed only by a holder of its still-held lock, in the order directory → lock pathname → close the lock fd; the fd is never closed before the unlink. Holders: `checkout` exit (`_forget`), the guard on R-2 (`_release`, through its transferred copy), and `_lease` for a pair it just created and verified. An acquisition that did not obtain ownership (the `O_EXCL` create failed, or the created lock is not its own any more) only closes its own fd and never unlinks a pathname. Repair targets at d2a1669: checks.py:317 (`_discard`), checks.py:333 (`_forget`) and check_guard.py:273 (`_release`) close the lock fd before the unlink. An interrupt or `OSError` during removal leaves the lock pathname (and whatever is left of the directory) for s1b1b2; an `OSError` never raises from cleanup, an interrupt is re-raised, and the fd is closed in a `finally` after the unlink attempt. Two no-op seams between directory removal and lock unlink, owned here for s1b1b2's A-W (3): `checks.forget_after_remove` and `check_guard.release_after_remove`.
