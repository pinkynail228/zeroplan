Background requests neither erase an interactive batch nor produce closing lines. Each completed interactive batch emits exactly one terminal catalog line from its own result: nonempty all-OK -> "Готово: всё в порядке." plus enabled next keys; failures -> all failing Check names and an enabled remedy key where available, otherwise a key-free remedy; empty -> "Нет результатов проверки."; error -> today's "Проверка не выполнена: ...". Use structured Check fields, not shortcut extraction from free text. Setup's existing post-install check supplies its result without a redundant check. Persist the Settings log across navigation; login/setup failure or cancellation is also visible on its originating goal/plan screen. Closing the app discards pending UI work and late deliveries under existing shutdown rules.
