s2a-home-binding — 0.5 item S2, part 1 of 3 (docs/RELEASE_0.5_SCOPE.md S2; docs/AGENT_ENV_PLAN.md design 2, the recovery contract). Every new native planning revision, milestone attempt and architect thread records the Codex home it starts in, and every later call for that record uses the recorded home. The default home does not change in this part (s2b does that), so this part changes no visible behavior for a fresh record. DeepSeek worker, sol reviewers.

Order: s2a -> s2b-agent-profile -> s2c-agent-usage; s2b must not merge before s2a, because switching the default home without a recorded home would resume old runs in the wrong home.

Rules:
- R-1 Home of an env. `setup.codex_home(env)` stays as it is: a nonempty `CODEX_HOME` in `env`, else ~/.codex, expanded and resolved. Add `setup.legacy_codex_home()` = `codex_home(os.environ)`. This is the home of a record from before 0.5, resolved from the process env the owner started zplan with. It is never resolved from an env that zplan has modified.
- R-2 Binding field. A binding recorded from now on has one more key, `codex_home`. Its value is `str(codex_home(env))`, where `env` is the exact env the engine passes to `zeroshot` (`native_environment()` of that engine). `toolchain.valid_binding` accepts the four old keys alone (a pre-0.5 record) or the four keys plus `codex_home`. If present, `codex_home` must be a str that is absolute, nonempty, has no NUL and is at most 4096 characters; anything else is an invalid record (the existing invalid-record refusal). The fixture binding {fixture_id} is unchanged.
- R-3 Identity vs. home. The engine identity is executable, state_root, sha256 and version. The checks at engine.py:676, runs.py:768 and planning.py:235 compare only these four fields. A different home is not an identity change, so a record never goes Stale or `engine.identity_changed` because of the home. `binary_identity()` keeps returning the four fields. The binding writers (engine.py:730, runs.py:634) add `codex_home`. Recorded-home resolution also applies to `recorded_engine()` (engine.py:548-552, called from `Authority.approve`/`override` at authority.py:761-762, :789-790), to approve/override revalidation, and to submitting an already prepared but unsent revision. Only the executable identity comparisons exclude codex_home. The frozen intent and approval digests keep it.
- R-4 Recorded home is used. `engine_for(binding)` returns an engine whose `native_environment()` has CODEX_HOME = the recorded `codex_home`, or `legacy_codex_home()` when the binding has no `codex_home`. Every other variable is the current env, plus the existing PATH prefix for another toolchain. It returns `self` only when the binary, version and that home all equal its own. This covers every per-record call: validate, submit, watch, status, force-stop, resume, logs, and the failure-cause read. A successor created by resume inherits the binding unchanged (LINEAGE). Nothing in a record's lifecycle rewrites `codex_home`. A missing recorded home directory is passed through as is, and the engine's own error surfaces; zplan never substitutes another home for a record.
- R-5 Architect thread home. The session record gains an optional `codex_home`, written in the same save that stores a new thread id (architect.py:639-642 `persist`). Its value is `codex_home(self.environment)`.
  - A resumed turn runs with CODEX_HOME = the recorded home, or `legacy_codex_home()` for a session without the field.
  - Resolve the next-turn home before the preparation auth checks (`default_prepare`, tui/chat.py:262-289), the header construction and Popen. A valid recorded home stays usable when the current home has no login. After reset, the previous thread's home is ignored.
  - Before a resumed turn, the turn is refused with a new family `architect.home_lost` and no Codex process starts when: the recorded home directory does not exist, or `codex_provider(home)` needs file auth (setup.py:411-438) and `home/auth.json` is not a file. The remedy text names the rollover: Ctrl+R "Новый диалог" (tui/app.py:788) starts a new thread in the current home. A provider that needs an env key, with that key unset, gets the same refusal.
  - `reset()` keeps working: the next turn starts a new thread and records the current home.
  - `load()` accepts a session without `codex_home`. If present, the field must satisfy R-2's value rule, otherwise `architect.session_corrupt`.
  - The chat header (tui/chat.py:244-258) shows the home the next turn will use: the recorded home for a continuation, the current home for a new thread.
- R-6 Architect stays read-only. Keep the explicit read-only argv of `build_argv` unchanged (`-s read-only` on a new thread, `-c sandbox_mode="read-only"` on resume). Before Popen, read the config.toml of the home the turn will use. A nonempty config-selected profile (top-level `profile`) refuses the turn with `architect.invalid_config` and no process. Do not claim that profile values outrank CLI overrides, or the reverse: the refusal is conservative. A top-level `sandbox_mode = "danger-full-access"` is not refused here; the installed check (A-8) shows whether the argv keeps the turn read-only. An unreadable config gives the existing `readiness.codex_home` refusal.
- R-7 No new default yet. New records record `codex_home(env)` of today's env. `zplan login`, doctor and the default home are unchanged (s2b). No credential file is read, copied or printed: auth is judged by file presence only, as today.
- R-8 Catalog: add `architect.home_lost` (what/why/remedy) and regenerate docs/REFERENCE.md.

Acceptance criteria (deterministic: fake `call`/Popen spies record the env of every `zeroshot`/`codex` invocation; temporary HOME/CODEX_HOME directories; no real provider):
- A-1 Binding shape: valid_binding accepts 4 keys, and 4 keys + codex_home. It rejects codex_home that is empty, relative, NUL-bearing, 4097 characters long, or not a str, and any other fifth key. A 4096-character absolute value is accepted. New planning revisions and new attempts store codex_home equal to the engine env's home.
- A-2 Every launch path uses the recorded home. Process env CODEX_HOME=B, record codex_home=A. Validate, submit, watch, status, force-stop, resume, the resumed successor's watch, log_tail, failure_cause and planning observation each spawn with CODEX_HOME=A. So do `recorded_engine()` under Authority.approve and override revalidation, and the submission of an already prepared but unsent revision. The same paths with the binary of an older toolchain also use A.
- A-3 Pre-0.5 records: a 4-key binding, with process env CODEX_HOME=L and an engine env whose CODEX_HOME=Z, spawns with L. With CODEX_HOME unset in the process env, it spawns with ~/.codex under the test HOME. Pre-0.5 records load and validate unchanged.
- A-4 A home change is not an identity change. Use separate fixtures: a submitted milestone record and an unsent prepared planning revision for identity checks; a proposed revision for approve; a review_exhausted revision for override. Changing only the current home causes no stale/identity refusal. Changing sha256 or state_root remains detectable. Frozen intent and approval digests include codex_home.
- A-5 Architect: a new thread records the home. A continuation spawns with the recorded home even when the current env has another home. A legacy session uses legacy_codex_home(). A missing home dir, a missing auth.json for file auth, and an unset key variable each refuse with architect.home_lost and zero Popen calls. After reset, the next turn spawns in the current home and records it. A malformed codex_home in the session gives architect.session_corrupt. The header shows the recorded home for a continuation. An integration test goes through `default_prepare`, not only `Architect.send`: a recorded home A with a login, and a current home B without one, prepares and continues in A. After reset, the same setup is refused for B's missing login.
- A-6 Read-only: argv equality tests for both argv forms stay green. A home with top-level danger-full-access still yields `-s read-only` / `-c sandbox_mode="read-only"`. Any nonempty config-selected profile refuses before Popen (zero Popen calls).
- A-7 Regressions: production-entry regression tests must reach the intended behavioral assertion on the named base. New-helper unit tests are excluded from base replay and covered by targeted mutations. Imports and fixtures must stay compatible with the replay base. Compatibility tests (A-3 legacy load, the argv equality tests) may pass on the base. Targeted mutations: drop the recorded home in `engine_for` or `recorded_engine`; compare whole bindings in check_binding; skip the home_lost check; check auth before resolving the recorded home. Record the exact targeted commands and the base failures. The existing engine, runs, planning, architect and chat suites stay green.
- A-8 Installed check (orchestrator, Linux test host, not the worker): real new-thread and resume architect turns, under a home whose config sets `sandbox_mode = "danger-full-access"`, attempt a file write and a git mutation in the project. Both are refused, and the project tree and refs are unchanged. The argv array alone does not prove this.
