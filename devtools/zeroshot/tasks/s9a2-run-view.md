Rules:
- R-1 One view, two UIs. `Delivery.run_view(r, streams, now)` is pure over the stored record plus the s9a1 stream results. It returns plain catalog lines in this order: Время, Этап, Модели, Итог, Дальше, Токены, Последний прогресс (the seven summary fields), then the tail section(s) as s9a1 renders them. The TUI and the plain UI render the same lines. Nothing is computed in a widget.
  - Время. Active (submitted/running/stopping): "идёт D" from `created` to now. Terminal: "до последней прочитанной записи журнала: D; время завершения неизвестно", from created to the run-wide stream's latest_timestamp. This is an observation interval, not the run duration. Missing created, no valid timestamp, or a timestamp before created gives "длительность: нет данных". D uses `live.duration`; never negative.
  - Этап. Show every currently observed node, retaining its node identifier alongside its catalog role. A task is shown only when the execution-to-task association is proven; otherwise "задача: нет данных". Never attach live.task to an unproven execution. Under the currently qualified public contracts, display "раунд: нет данных". live.workers may be displayed separately as "наблюдавшихся визитов исполнителя: N"; live.repairs remains an explicitly observed count. Neither counter is a native review-round number. Supporting a numeric native review round requires a separately gated public-contract proof. Terminal records show the last observed stage, labelled as observed, or "нет данных". Do not infer stage or round from log prose.
  - Модели. One entry per observed node: "<node> (<role>): задано M/E; фактически: нет данных". Node -> role through the existing milestone graph role map; a node the map does not bind -> "задано: нет данных". A terminal record shows the three configured bindings with the same "фактически: нет данных". The configured binding is never labelled as the one actually used.
  - Итог. Active: "ещё идёт". Detached: "наблюдение прервано — состояние неизвестно, [w] подключиться", never failed or finished. Terminal: the `run_state` text plus, for failed/failed_recoverable, the S4 catalog line verbatim (observational prefix, class, remedy, reset). Failure is never inferred from a log line or level.
  - Дальше. The same mapping home and RunScreen use (`next_step` / END_ACTIONS): one function, no second table. A historical attempt shows "историческая попытка — только просмотр". Historical means its full identity differs from the current revision's latest attempt for that milestone. The view offers only its documented close/navigation bindings.
  - Токены. Active: "Токены: нет данных до завершения". Terminal: S2c `usage_line(r.get("usage"))`.
  - Последний прогресс. P = max(`live.last_event`, run-wide latest_timestamp), rendered "HH:MM:SS (D назад)", or "нет данных". Stall: an active attempt with now - P >= STALL_SECONDS (900) shows "нет прогресса с HH:MM:SS (D)". Display-only, no action. Home keeps its exact label «последнее событие».
- R-2 Attempt selection. TUI [e] opens an attempt selector for the selected milestone, newest first, including every stored attempt with a run_id and every resume successor. Selection uses (plan_revision, milestone, attempt, run_id), never the attempt number alone. Opening the selector performs no native read. The selected RunViewScreen is read-only; a historical attempt cannot invoke current-attempt mutations. The plain UI offers the same selection. Titles include revision, milestone, attempt and a distinguishing run-id suffix. [e] in the end modal opens the modal attempt's RunViewScreen directly. The screen scrolls and closes with esc/q. Update `tailable`/`tail_item` and the key bars. The planner tail keeps its entry point and uses the s9a1 run-wide rendering only (unattributed).
- R-3 Refresh scheduling. Reads are the existing coalesced, cuttable "tail" job calling the s9a1 reader; never from the home refresh or an observe slice. An active attempt re-reads every TAIL_REFRESH (10 s) after the previous read ended. While open, refresh the presentation from the latest stored attempt snapshot and current time, independently of new log lines. A transition to terminal stops active scheduling and permits one final read per stream. Closing invalidates pending callbacks. Closing or Ctrl+Q cancels the reader through its handle and reaps it within the remaining QUIT_BUDGET; only reader processes are terminated. A failed refresh keeps the shown lines and adds "журнал не обновлён: <summary>" (scrubbed by s9a1). No stop, resume, retry, model call, sqlite read or HTTP history call in this path.
- R-4 Layout: at 80x24 and 120x40 the seven summary fields occupy at most 14 rows; values are bounded by terminal-cell width with explicit "…"; full scrubbed values stay in scrollable details. Render literal Rich Text or markup=False.
- R-5 Text through the catalog, REFERENCE regenerated, docs/USER_FLOW.md "Live run" describes the selector and the view.
