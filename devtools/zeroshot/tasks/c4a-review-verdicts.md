Acceptance criteria:
- A1 New live key `verdicts`: a list of at most 8 entries, newest last, each {"at": stamp, "task": str or None, "round": int ≥ 1 or None, "role": "acceptance_review" | "code_review", "verdict": str ≤ 16 chars, "text": str ≤ 160 chars}. `new()` sets []. `valid()` accepts a stored record that lacks `verdicts` and/or `command` (both optional keys of older records); any other missing or extra key is still refused.
- A2 Departure: when a watch record's active executions no longer contain an execution whose node base (`live.base`) is acceptance_review or code_review and that was in the previous `live["nodes"]`, that execution is queued with the `live["task"]` and `live["workers"]` (round; None when `task` is None or workers is 0) of the moment before `stages` updates them. The queue lives in memory on `MilestoneRuns` per run id (like `self.commands`), at most 8, no duplicates; nothing new is persisted besides `verdicts`.
- A3 Read: at the end of a completed slice, if the run's queue is not empty, zplan reads `logs RUN --execution REF` for the oldest queued execution (deadline 2 s, the existing bounded buffer `LOG_LIMIT`) and in that slice makes no C3a command read; otherwise the C3a rule applies unchanged. The retained lines are used whatever `complete` says. An entry is dropped from the queue after a read that finds its response, or after its second read that finds none; an OSError counts as a read.
- A4 Parse: the last line whose `record.message` decodes as JSON with `response.signals.verdict` a non-empty string; `verdict` = that string cut to 16 chars; `text` = the first non-empty line of `response.diagnostic.message` (empty string when absent), scrubbed with `live.scrub`, cut to 160 chars; `at` = the record's ms `timestamp` floored like C3a (`live.floored`). Lines that do not decode, or lack these fields, are ignored.
- A5 A found verdict appends one entry (bounded to 8, oldest dropped); the same execution is never appended twice (dedupe in memory by execution id per run). No exception escapes `observe`.
- A6 Tests: parser (accepted; rejected with a multi-line diagnostic keeps line one; credential in the diagnostic scrubbed; malformed JSON and debug lines ignored; cut at 160/16) using a fixture line copied from the measured shape above; validator (record without `verdicts`, without both optional keys, with them; extra key refused); departure (a reviewer leaving is queued with task/round of that moment, a worker leaving is not); observe with a fake driver (verdict read takes the slice instead of the command read; OSError twice drops the entry; a found verdict appended once).

Non-goals (reviewers must not require): any panel or TUI change (C4b), final_verify / scope_verify verdicts, the planner (planning.py), comparing findings across rounds, migration of stored records, reading a run's history API.
