Rules:
- R-1 Replay. A bounded, cancellable reader (same mechanics and handle as `live.tail`/s9a1; no sqlite, no HTTP history, no `zeroshot ui`) reads `zeroshot watch RUN` from the start and parses the snapshot sequence in order without dropping its prefix. Result: ordered executions {execution, node, first_cursor, last_seen_cursor, active_in_latest}, plus `complete: bool` and a reason. Incomplete history = timeout, byte or snapshot overflow (WATCH_BYTES, WATCH_SNAPSHOTS), a malformed line, or a terminal record whose replay did not reach a terminal snapshot. Never detect gaps from cursor arithmetic. Duplicate snapshots are idempotent. For an active run the next read continues with `--after` the last parsed cursor; it never claims to refill a lost prefix. Replay is read-only: no conclude, export, record write or lifecycle effect. The result lives in memory for the open view; only s9a1's bounded `execution_nodes` stays persisted.
- R-2 Topology. Grouping is allowed only when the attempt's frozen graph document is the zplan milestone graph (recompute `milestone.milestone_graph` for the stored baseline/checker and compare with the frozen document identity the record already stores; re-check the field on base). Any other, unidentifiable or legacy graph -> ungrouped execution timeline with "группировка недоступна: <reason>". Under the supported graph, project in first-observed order:
  - `select_init` -> preparation; each `select` execution opens task cycle k; `select_verify`, `steward_apply`, `steward_decide` belong to the open task cycle;
  - each `worker` execution opens review cycle j inside the open task cycle; `acceptance_review`/`code_review` executions after it belong to that review cycle (parallel, ordered by node name);
  - final stage separately: `final_verify`, then each `repair` opens repair cycle j with `scope_verify` and `final_reverify`; the `empty_` variants are the same stage labelled "пустая очередь";
  - a second execution of a node inside the same cycle without a new cycle opener is a separate entry marked "повтор";
  - any node outside ROLES, or an order the rules above cannot place (a reviewer before any worker in its task cycle, a task-cycle node before the first `select`), makes the whole run ungrouped with the reason; never a partial guess.
  Labels say observed: "задача-цикл k (наблюдаемый)", "проверка-цикл j (наблюдаемый)". No "из N" for active runs; terminal runs show "наблюдалось: N". The task id is shown only through the existing execution-task proof (`live.execution_task`); otherwise "задача: нет данных". Execution status is "активно" (in the latest snapshot) or "больше не активно"; never success/failed. A resume successor is a separate run with its own numbering; the projection carries a lineage line to its predecessor.
- R-3 Response, parse before scrub. Per execution, take only the last observed info record from its `--execution` stream (s9a1 grammar). Chain: decode the bounded envelope -> parse the complete message as JSON against that node's contract in the frozen graph (verifier: `signals.<signal>` in the node's labels, `diagnostic` with the node's fields; step: its output kind) -> extract fields -> split `diagnostic.message` into findings under a closed grammar (items start a line with `N.` or `N)`, N = 1..n consecutive; otherwise one item) -> scrub each field with s9a1 scrub -> apply bounds (preview TAIL_TEXT 300; full diagnostic up to DIAGNOSTIC_TEXT for drill-in). A message that is truncated, redacted, not JSON, off-contract, or not the last info record -> "ответ: нет данных"; never search earlier records for a better answer. Display label for verifiers: «Ответ ревьюера: <label>; принятие движком неизвестно» (stewards: «Ответ стюарда: …»). The raw response is never shown or stored. The answer never drives Итог, lifecycle, the cycle status or any action.
- R-4 Agent activity. Per execution: «последнее сообщение агента» = the last info record that is not the response (scrubbed preview, full bounded text for drill-in); «последняя наблюдавшаяся команда/действие» = the last debug record matching the Codex adapter prefixes (command started/completed, file change), labelled as observed, never "сейчас выполняет". Unknown prefixes are not shown as actions.
- R-5 Bounds. Reuse EXECUTIONS_LIMIT for executions shown ("показаны последние N из M"), TAIL_LINES/TAIL_TEXT per stream, a per-view read budget inside the existing tail job; constants named in one place. Totality over arbitrary bytes as in s9a1 (no exception escapes).
- R-6 Shape. One pure function, e.g. `flow.project(graph_supported, replay, streams, record) -> Flow` (plain data, no Textual, no catalog rendering beyond catalog ids/params), plus the reader. s9a2b renders it.
