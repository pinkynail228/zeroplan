Today a version 2 revision whose plan gate ended with the critic's `rejected` (status `review_exhausted`; exhausted rounds = rejected) can only be revised or restarted. Add: the owner approves it anyway with a typed reason.

Authority (the only place the rule lives; UI only calls it):
- `override(version, reason, live_digest=None)` approves the current revision in one locked transition, allowed only when ALL hold: status `review_exhausted`; execution version 2 (a version 1 revision has no gate: refused); `check_evidence` passes and the gate's `critic_verdict` is `rejected`; the project baseline is fresh (same refusal and family as approve, `plan.stale`); `live_digest` (when given) equals the gate's `resolved_config_digest` (`plan.gate_stale`, as approve); `check_bounds` and the native `prepare` exactly as approve. Refused otherwise; a refusal writes nothing (planning.json bytes unchanged). The service method `Planning.override(version, reason)` always passes `self.profile.live_digest()` (as `Planning.approve`, planning.py:347); every UI path goes through it, never authority directly with `None`.
- Reason: `reason.strip()`, single line, 10..500 characters; otherwise refused with a clear message (family `action.refused`). No reason, no override.
- Record: the revision gets `override = {"reason": <stripped text>, "verdict": "rejected", "evidence_digest": digest(evidence)}`; evidence (including `critic_verdict`, findings, discussion) stays byte-identical; status becomes `approved`; `approval` is computed as for approve and must also bind the override (tampering with the reason after approval fails validation). Revisions without an override keep their current approval identity and stored bytes: existing planning.json files load and validate unchanged, nothing is rewritten on read.
- Schema: `override` is an optional field in the strict revision schema (authority.py ~446); an absent/None override is not added to the approval identity (authority.py:574), so already approved records of BOTH execution versions keep their approval digest and stored bytes.
- Validation: `approved` requires verdict `accepted`, or verdict `rejected` with a valid override bound as above; `override` is absent/None on every other revision and status; an override with `verdict`/`evidence_digest` not matching the evidence is invalid.
- Everything that consumes an approved plan (milestone start, delivery, status lines) works for an overridden plan exactly as for an accepted one; no other gate (task/merge) is affected.

The `[i]` gate details (planning.py ~517) show the override and its reason next to the verdict and discussion; the line "утвердить этот план нельзя" (planning.py ~520) is replaced by the override line for an overridden revision (pass the owner record to `gate_lines` separately from the evidence).
