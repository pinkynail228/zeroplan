Rules:
- R-D Descriptors. Every descriptor is held by an object that owns it (`socket.socket`, a `Popen` pipe, a file object, or an `int` closed in exactly one place right after the spawn that transferred it). A process closes only descriptors it owns: ones it opened, or ones explicitly transferred to it (the guard owns its inherited lifeline end and its lease lock copy and closes them under R-K). A borrowed descriptor (the lease lock fd that `run_check` passes on but `checkout` owns) is never closed by the borrower. No code retries a close or compares descriptor identity (st_dev/st_ino/flags). Non-goal, stated in the receipt: a KeyboardInterrupt or other asynchronous exception arriving during acquisition or cleanup may leak descriptors of that interrupted call (bounded per call, freed at process exit); it must never close a descriptor the process does not own.
- R-A Argv. A `check["argv"]` element containing NUL raises `ValueError` before any descriptor or process is created. A missing executable is `spawn_failed` (parent A-F).
- R-F Failure mapping. An `OSError` from `socketpair`, `popen` (including `EMFILE`) → `spawn_failed`, empty tail, `duration_s` from the injected clock, no guard alive. Lifeline EOF before `S` or `F` → `spawn_failed`, empty tail. EOF after `S` without `X` → status `timeout`, never a numeric status.
- R-X Exceptions. The original exception (including `KeyboardInterrupt`) is the one re-raised after cleanup; an `OSError` raised by a cleanup step is swallowed and never replaces it. An interrupt during cleanup propagates; the stop then counts as unconfirmed (R-C). No further guarantee for interrupts during cleanup (R-D non-goal).
- R-C Confirmed stop (fail-closed; protects S1c merge rule s1c1c-merge-rule.md:25 from a false pass). Cleanup is confirmed only when the guard has been reaped within `REAP` and, if `S` was received, `os.killpg(C, 0)` raises `ProcessLookupError`. Otherwise, with an original exception it is re-raised; with none, `run_check` returns status `timeout` whatever `X` said (an `X 0` never yields status 0). The unreaped guard `Popen` is appended to a module-level list `ORPHANS` (guarded by one module-level `threading.Lock`); every later `run_check` entry and every `checkout` exit polls it and drops exited entries (reaped, never waited on, never killed). If `cwd` is a lease, `checkout`'s exit then drops the registration and closes its lock fd but removes neither the directory nor the lock file (the leftover is s1b1b2's).
- R-K Lease cleanup under ownership. A lease's directory and lock pathname are removed only by a holder of its still-held lock, in the order directory → lock pathname unlink → close the lock fd. Holders: `checkout` exit, the guard on R-2 (through its transferred copy), and `_lease` for a pair it just created. An acquisition that did not obtain ownership (the `O_EXCL` create failed) closes only its own fd and unlinks nothing; it never removes a pre-existing entry (keep the a9107fc collision test). An `OSError` during removal is swallowed and leaves the rest for s1b1b2. Seams for s1b1b2 A-W: module-level no-op hooks `checks.forget_after_remove` and `check_guard.release_after_remove` between directory removal and the lock unlink, plus `check_guard.after_report` after the guard sends `X`.
