Rules:
- R-1 Scope (parent R-1): with `gates.merge == "off"` (preset `/1`), or a fixture authority (`authority.fixture_id` not None) without a profile, every record, digest, screen, refusal and the merge path are byte-identical to base; no `check_overrides` key.
- R-1b Fail closed: a native authority (`fixture_id is None`) with no bound profile (`authority.profile is None`) refuses `Runs.merge` with `process.missing` before any side effect; a profile that is pending, missing or malformed refuses as `Profile.guard` :693-704. If an existing test merges through a native authority without a profile, stop and re-gate (do not edit it).
- R-2 Live values: `live = {commit, tree}` from `r["result"]`; `destination_head` = the destination branch HEAD; `qualification_id` from the newest qualification (None for checks=[]); `checks_digest` computed from the currently resolved checks of the live profile (the same digest function s1b2a uses for the record's `checks_digest`; `digest([])` for checks=[]), never copied from the qualification record (critic gate23: otherwise `current` compares the record with itself); `config_digest` of the live resolved config (`status(write=False)`).
- R-3 Merge rule (parent R-2 merge part and R-5), evaluated in this order, the first failing step decides the family; all before any side effect:
  1. checks non-empty and the newest qualification is not concluded or not `current` (none, running, interrupted, refused, stale) → `merge.qual_missing`;
  2. current failed qualification without a valid failed-checks override (R-6) → `merge.qual_failed`;
  3. newest merge gate of `r` absent, nonterminal, `native_failed` or `output_invalid` → `merge.gate_missing` (text names the state);
  4. concluded gate whose `identity` does not match `live` → `merge.gate_stale`;
  5. `critic_verdict != "accepted"` without an override passing `override_matches(merge_gate.evidence(record), override, verdict_field="critic_verdict", subject=SUBJECT)` → `merge.gate_rejected`.
  checks=[] skips 1-2 and binds qualification_id None (display "без квалификации", never "passed").
- R-4 Enforcement inside Runs (critic gate22): `Runs.merge` calls `merge_admission(r)` first — after the read-only `check_current` :1140 and before `upgrade(r)` :1141 and `refresh()` :1143, so a refusal writes nothing — with `destination_head = git rev-parse refs/heads/<branch>` (argv only); then again `merge_admission(r, head)` with `head` from :1154 immediately before `git merge` :1156. A recheck refusal leaves refs, HEAD, the working tree and the store unchanged. `merge_admission` resolves the profile (R-1/R-1b), returns at once under off, and otherwise applies R-3 through `merge_gate.admission`. `Delivery.merge` keeps its profile guard and only calls `Runs.merge`; it holds no rule of its own. Conflict retries (`delivery == "conflict"`) follow the same rule.
- R-5 Gate override (parent R-6): `override_merge_gate(gate_id, reason)` only on the newest concluded record of the latest attempt whose `critic_verdict == "rejected"` (exhaustion included) and whose identity matches `live`; reason through `override_reason`; stores `override = {reason, verdict, evidence_digest}` on that record (the one allowed edit); `critic_verdict` stays. Missing, nonterminal, stale, native_failed, output_invalid → `action.refused`, store unchanged.
- R-6 Failed-checks override (parent R-6): a separate record in `state["check_overrides"]`, exact keys `{id ("check-override-" + uuid4), qualification, identity: {commit, tree, destination_head, checks_digest}, failed_checks, not_run, reason, created}`. `failed_checks` = names whose status is a nonzero int, `timeout` or `spawn_failed`, in profile order (1..`MAX_CHECKS`); `not_run` = the names never run (0..7). Allowed only for the newest concluded failed `current` qualification; reason through `override_reason`. Valid iff its qualification is still the newest, still current, and identity equal; a new qualification or any identity change invalidates it. It changes neither the qualification outcome nor any critic verdict. Missing, running, stale, interrupted and refused qualifications cannot be overridden (`action.refused`). Strict validation → `store.invalid`.
