ds-export-check — content and manifest check for the public export (docs/P0_AUDIT.md, "Export check script"). DeepSeek calibration, grade medium. Devtools only: no change to terminal_planner/, tests/, install.py, docs.
Out of scope (separate P0 gate, done by the export step later): commit/tag metadata and messages of the public repository.

Build `devtools/export_check.py` (stdlib only, Python 3.11+) and `devtools/test_export_check.py`.

Inputs: `--commit REV` (default HEAD) of a git repository (`--repo`, default the cwd's git toplevel); everything is read from REV (`git ls-tree -r -z REV`, `git cat-file`), never from the working tree: the manifest and the exemptions too (`REV:devtools/export-manifest.txt`, `REV:devtools/export-exemptions.txt`). Working-tree edits never change the result for the same REV.

1. Export set. `devtools/export-manifest.txt`: one pattern per line, `+ PATTERN` include, `- PATTERN` exclude, `#` comments. A pattern ending in `/` matches that directory prefix; otherwise `fnmatch.fnmatchcase` on the full repo-relative path (`*` crosses `/`). A path is exported when it matches an include and no exclude (exclude wins). Initial content from P0_AUDIT.md "Include"/"Exclude"; also exclude docs/P0_AUDIT.md and STATE.md.
2. Entry types. In the export set only regular files (modes 100644/100755) are allowed; a symlink (120000) or gitlink (160000) is a finding (`symlink`, `gitlink`). A blob that is not valid UTF-8 is a finding (`unreadable`). No escape hatches for binary, symlink or gitlink in this version.
3. `--dir PATH` (optional): the exported tree on disk must equal the export set: same paths, regular files only, byte-identical content to the REV blob, same executable bit. Extra, missing, changed or wrong-type entries are findings (`dir-extra`, `dir-missing`, `dir-changed`).
4. Content rules, applied per line of every exported blob (rule names in brackets):
   [openai] `sk-[A-Za-z0-9_-]{20,}` not followed by `ant-`; [anthropic] `sk-ant-[A-Za-z0-9_-]{20,}`; [github] `ghp_[A-Za-z0-9]{36}` or `github_pat_[A-Za-z0-9_]{22,}`; [aws] `AKIA[0-9A-Z]{16}`; [slack] `xox[abprs]-[A-Za-z0-9-]{10,}`; [google] `AIza[0-9A-Za-z_-]{35}`; [yandex] `(y0_|AQVN)[A-Za-z0-9_-]{20,}`; [private-key] `-----BEGIN [A-Z ]*PRIVATE KEY-----`; [jwt] `eyJ[A-Za-z0-9_-]{10,}\.eyJ[A-Za-z0-9_-]{10,}\.[A-Za-z0-9_-]{10,}`; [credential] `(api_key|token|password|secret)\s*[:=]\s*["'][^"'\s]{8,}["']` (case-insensitive); [url-userinfo] `[a-z][a-z0-9+.-]*://[^/\s:@]+:[^/\s@]+@`; [bearer] `Bearer\s+[A-Za-z0-9._~+/-]{16,}`; [home-path] `/(Users|home)/([A-Za-z0-9._-]+)` where the name is not `user`, `testuser`, `runner`.
   No placeholder heuristics: known test fixtures are handled by exemptions (later, by the owner).
5. Private terms: `--private-terms FILE` (outside the repo; one literal per line, case-insensitive) checked in blob lines [private-term] and in paths [private-path]. Without `--private-terms` the run still checks everything else, prints `private-term rule skipped`, and exits 3 when there are no other findings.
6. Exemptions: `devtools/export-exemptions.txt` lines `path<TAB>rule<TAB>sha256-hex of the full line`; silences exactly that line for that rule; an exemption that matches no finding is a finding (`stale-exemption`).

Output (stdout and stderr, including error messages): never a matched value, line text or private term. A finding is `rule<TAB>path<TAB>line` (line 0 for path/type findings); a path that matches any content rule or contains a private term (also `--dir` extra entries) is printed as `<redacted:FIRST12HEX>` (sha256 of the path) and reported once as `secret-path` / `private-path`. Last line: `summary: N findings` plus `rule=count` per rule. Exit 0 clean, 1 findings, 2 usage/git error, 3 incomplete (private terms missing, otherwise clean).

Self-tests (`python3 -m unittest discover -s devtools -p 'test_export*'`): throwaway git repos in a temp dir, synthetic data only (no real names, hosts or keys); build key-shaped fixtures by string concatenation so the test file itself does not match a rule. Cover: clean repo exits 0; one positive per content rule plus one near-miss negative for openai/anthropic and home-path allowlist; private term in content and in a path (path redacted); file outside include not scanned; excluded file with a secret passes; exclude wins over include; symlink, gitlink (add with `git update-index --cacheinfo 160000,...`) and non-UTF-8 blob each fail; `--dir`: extra file, missing file, same name with changed content (a secret), each fail; exemption silences only its line; stale exemption fails; manifest edited in the working tree but not committed does not change the result; missing `--private-terms` exits 3. A key-shaped file name (also as a `--dir` extra file) is redacted. Every test checks that the combined stdout+stderr contains none of its synthetic secrets or terms.
