Rules (parent R-4/R-5 restated as a closed grammar; each: structural rule, domain, boundaries, states; checks in Acceptance):
- R-4 `sweep(root)` → `{"removed": int, "busy": int}`, does not raise on filesystem `OSError` (parent R-4); asynchronous exceptions may propagate under the interrupted-call limits stated above. Domain: only names directly under `root` that start with `PREFIX`; everything else under `root`, and everything outside `root`, is untouched. Classification uses `lstat` only (never follows a link):
  | name / type (lstat) | role |
  |---|---|
  | ends with `.lock`, regular file | a lock; belongs to the entry named without `.lock` if that name exists (lexists), else an orphan lock |
  | ends with `.lock`, symlink (live or dangling) or other non-directory non-regular type | not a lock zplan creates: a lockless entry, unlinked (never opened, never followed) |
  | ends with `.lock`, directory | an entry (a checkout without a valid lock), never a lock |
  | any other name: directory, regular file, symlink (live or dangling), other type | an entry; its lock is `name + ".lock"` only if that is a regular file |
  Per entry, in descending name-length order (so a directory `X.lock` is handled before `X`'s lock is examined): every removal follows R-W. A lock name that is not a regular file (symlink, dangling symlink, fifo, other) is not a lease lock: it is unlinked first (never opened, never followed) and the entry proceeds as lockless. A held lock → busy, left in place. Directory entries are removed with the s1b1b1r `_remove` (never follows or chmods through a link); any other type with `unlink`; the lock last. An orphan lock (no entry): removed under R-W; held → busy (a lease being acquired).
- R-V Counting. Success only when afterwards neither the entry nor its lock `lexists`; otherwise busy. Missing `root` → zeros. `root` that exists but cannot be listed, or is not a directory → `{"removed": 0, "busy": 1}`. Any `OSError` on an entry → busy for that entry. A symlinked `root` itself is listed as given (the caller owns `root`).
- Fault model and product need: prevent sweep from deleting a live or newly published checkout. The model covers cooperating checkout, guard and sweep actors following this protocol, their scheduling interleavings, static leftover shapes in R-4, and filesystem errors in R-V; A-W supplies deterministic examples, not a closed corpus. Concurrent filesystem mutation by actors outside this protocol and completion of cleanup under asynchronous exceptions during acquisition/removal are non-goals. R-D's prohibition on closing unowned descriptors remains. This slice amends s1b1b1r R-D's identity-comparison ban only for the `fstat(fd)`/`lstat(lock_path)` checks below, which establish lock-path ownership; descriptor-reuse recovery, identity-based close/retry and the dropped R-O machinery remain excluded.
- R-W One serialization for publication and removal (critic gate17). Structural rule: a `checkout-*` name is owned only by the holder of `flock(LOCK_EX)` on the inode *currently* at its lock path; holding a lock on an inode no longer at the path grants nothing. Publication (`_lease`): create the lock `O_CREAT | O_EXCL | O_NOFOLLOW` 0600, `flock(LOCK_EX)`, then verify `fstat(fd)` (st_dev, st_ino) equals `lstat(path)` and st_nlink > 0; only then create the directory and register the lease; a failed check closes only its own fd and retries a fresh name within `TRIES`. Removal (`sweep`): open the existing lock `O_RDWR | O_NOFOLLOW | O_NONBLOCK`, or for a lockless entry create its own lock as publication does; `flock(LOCK_EX | LOCK_NB)`; then re-verify `fstat(fd)` against `lstat(path)` (same dev/ino, regular, st_nlink > 0); a mismatch or absent path → release, count busy, remove nothing; a match → remove the entry, unlink the lock, close the fd, all while the lock is held. `O_EXCL` failure when sweep creates a lock → busy. States: old lease ending, new lease publishing the same name, sweep between open and flock; sweep holding a verified lock while a publication's `O_EXCL` fails.
- R-P Project inside root. `checkout` raises `ValueError` when the resolved project is `root` or lies under `root` (s1b1b1r already refuses root inside the project). This is the remaining collision that `sweep` could otherwise turn into a real loss (a project at `root/checkout-*` is a lockless entry by R-4). The R4 lease collision itself (a pre-existing entry at the random name) is s1b1b1r's and stays covered by its test.
- R-5 Rerun gate (parent R-5 verbatim): a new qualification starts only after `sweep(root)` returns `busy == 0`; a leftover held by an orphan of group C stays busy until that holder exits; the parent R-3 guard-kill limit applies (busy is not guaranteed after a direct guard kill).
- R-7 Parent R-7 applies (no user text; programming errors are `ValueError`; home paths in fixtures only under `/home/user/`).
