# Roadmap (2026-11-05, revision 11): the plan to the target flow

**Goal in the owner's words.** Set the goal together with the architect and approve the plan once. Get merged,
verified branches without babysitting.

**The target flow** is section 0 of `docs/designs/2026-11-04-w0-worker-contract.md`:
1. The owner states a goal and gets one checked plan card.
2. He says yes once.
3. Zeroshot runs fixed profiles, and zplan verifies and merges.
4. The owner reads one report.

Earlier revisions are in `git log -p` of this file. `STATE.md` says which step is in progress.

**Final acceptance.** The target flow runs on the installed product with the real provider. Each step must hold:
- a new project with no tests;
- a goal of three slices;
- one yes;
- merged branches;
- one report;
- zero manual interventions (`PRODUCT_CONTRACT.md` section 9).

**Order.**
- F0 first: every later slice runs under it. P1 in parallel (the Elephant's own change).
- P3 and P4 run alongside P1 and P2: they change the architect, not the engine.
- P5 follows P4.
- P6 follows P2, and P7 follows P6.
- P8 and P9 follow P7.
- P10 comes last; T2 starts after P7.
