# Roadmap (2026-11-05, revision 12): from 0.11 to the target flow

**Goal in the owner's words.** Set the goal together with the architect and approve the plan once. Get merged,
verified branches without babysitting.

**Terms.**
- *zplan*: this product, the terminal app.
- *Zeroshot*: the engine that runs one milestone as a graph of agents.
- *The architect*: zplan's chat agent, which talks to the owner and writes the plan.
- *The plan card*: the plan shown for the owner's yes.
- *Brief*: what a plan gives each task: goal, write set (the files it may change), acceptance criteria, done-when.
- *Candidate*: the exact tree a milestone produced.
- *Base check*: a project check (`zplan.process.json`) run on the commit the work starts from.
- *Full lane*: every test of this repository (`devtools/fasttest.py --lane full`).
- *Elephant and Goldfish* (the Elephant-Goldfish Model,
  https://opensource.googleblog.com/2026/10/introducing-elephant-goldfish-model-plugin.html): the Elephant is the one
  session that holds the context and the design; Goldfish are stateless sessions that validate a specification
  before code, in three steps: a comprehension check (retell it), antagonistic reviews, and an implementation
  readiness check (go or no-go: is everything the implementer needs present and unambiguous). In zplan the architect
  is the Elephant, and the plan check runs the first two steps (a reader retells the plan, a critic checks it). In
  development the Elephant is the architect of this repository, `devtools/goldfish.sh` ("Astra") runs the reviews,
  and the slice runner's contract review is the readiness check.
- *W0*: `docs/designs/2026-11-04-w0-worker-contract.md`.

**The target flow for 0.12.**
1. The owner states a goal and gets one checked plan card.
2. He says yes once.
3. Zeroshot runs the milestones, and zplan verifies them on the exact candidate and merges them.
4. The owner reads one report: what merged, the architect's decisions and assumptions, the checks that passed, and
   what is not verified.

This is W0 section 0 without five parts, each in the backlog with what brings it back:
- the graphs as installed profiles;
- the worker's `BLOCKED` route;
- the per-plan record;
- the proposal at plan end;
- a plan's first check gating the merge of its own milestone (R2).

Revision 12 follows the plan review with the owner on 2026-11-05. The owner accepted every verdict, including the
three that change his earlier decisions: profiles deferred, the report simplified, and T2's batches replaced by a
rule. The review's record is the commit of this revision and `STATE.md`. The day before, rig-gated format work had not
moved the target flow, while the first live runs on a real project found the actual gaps in one evening. Earlier
revisions are in `git log -p` of this file, and `STATE.md` says which step is in progress.

## How an item earns a place in the plan

An item stays only if at least one of these holds:
- it blocks the target flow on a real project;
- it is a failure someone observed;
- it is a product rule or the owner's explicit decision.

Everything else is cancelled, or deferred with the event that brings it back. R1 and R2 change verification and
merge rules, so each gets a short design and one Goldfish pass before it is built (`DEVELOPMENT.md` section 2,
Proportion). R3 and R4 are direct changes.

## 0.13: the plan check as the full Goldfish protocol

The plan check has no implementation readiness step before the owner's yes. Each brief, the part a worker carries
out literally, is first checked by `preflight` inside the milestone run, after the yes. In the first live run one
brief line that a worker could not satisfy cost an attempt, and `preflight` passed it.

0.13 moves that readiness check into the plan check: one more step there, not a new role. `preflight` keeps checking
the brief against the base as it is when the run starts. Several critics, and a Goldfish that compares the merged
result with the owner's words, are decided at the same time. The design starts from the role outcomes that the 0.12
release counts: which Goldfish node caught what, and which caught nothing.
